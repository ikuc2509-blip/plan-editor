# Редактор плана места происшествия

Приложение для составления развёрнутого плана помещения (план-схемы) при осмотре места происшествия: план пола, развёртка стен, метки обнаруженных объектов, легенда, примечания, штамп. Результат — PDF для печати и подписи; план прилагается к протоколу осмотра (ч. 8 ст. 166 УПК РФ).

Учебный проект для семинара по криминалистике, сделан «как настоящий». Главная функция в перспективе — построение плана по фотографиям осмотра.

- Полные решения по всем темам: `docs/decisions.md`. Если что-то непонятно — сначала смотри туда.
- План работ по этапам: `TODO.md`.
- Исходный прототип (рабочий, одна HTML-страница): `prototype/plan-editor.html`.
- Образец оформления листа: `prototype/plan_razvertka.py` и `prototype/obrazec_razvernutyi_plan.pdf`.

## Кто заказчик

Пользователь — студент-юрист, начинающий вайбкодер, **не программист**. Код он не читает.

- Объясняй простым языком, без жаргона; термин — сразу с пояснением.
- Перед этапом или крупной правкой — короткий план (что будет сделано, какие файлы, что изменится для пользователя). Жди «ок».
- После этапа — «Как проверить руками»: 3–7 шагов, что нажать и что должно получиться.
- Если решения нет в `docs/decisions.md` — спроси, дай 2–3 варианта с плюсами и минусами. Не выдумывай требования.

## Жёсткие правила (нарушать нельзя)

1. **Никаких сетевых запросов** после установки. Шрифты, библиотеки, иконки — внутри приложения. Нет CDN, Google Fonts, аналитики, счётчиков, отчётов об ошибках. Content-Security-Policy разрешает загрузку только с адреса самого приложения (`'self'`). Причина — тайна следствия (ст. 161 УПК РФ).
2. **Никакого облака.** Нет кнопок «поделиться» в мессенджеры, почту, облачные диски. Нет облачного распознавания фото. Проект передаётся только файлом `.omp` (USB, флешка).
3. **Только открытые лицензии:** MIT, Apache-2.0, BSD, ISC, Zlib; для шрифтов — OFL. **Нельзя:** GPL, AGPL, LGPL, «только некоммерческое использование», модели Ultralytics YOLO. Перед добавлением любой зависимости — проверь лицензию и спроси пользователя. Версии зависимостей фиксируются в `package-lock.json`.
4. **В репозитории только код и учебный пример.** Репозиторий публичный (GitHub Pages). Никаких снимков, файлов `.omp` и данных реальных осмотров. Тестовые данные — только учебная аудитория с семинара (`examples/`).
5. **Обновление — только по кнопке** «Доступна новая версия». Никогда не обновлять приложение само посреди работы.
6. **На лист ничего не попадает без подтверждения пользователя.** Всё, что создано модулем «по фото», имеет статус «условно» и лежит в слое «предложений», пока его не приняли.
7. **Оригиналы фотографий не изменяются** (ни сжатия, ни поворота, ни удаления EXIF). Для интерфейса — отдельные превью.
8. **Формат файла проекта версионируется.** Любое изменение `plan.json` — повышение версии формата и миграция старых проектов + тест на открытие старого файла.

## Устройство приложения

Три слоя, зависимости идут только сверху вниз:

1. **Модель** (`src/model/`) — данные плана и правила их изменения. Без DOM, без Preact. Здесь же единицы, замеры, автопроверки, миграции формата.
2. **Рисование** (`src/render/`) — одна функция «план + формат листа → SVG». **Один и тот же код** рисует лист на экране, в PDF, SVG и PNG. Не делать отдельный «рисунок для печати».
3. **Интерфейс** (`src/ui/`) — два режима над одной моделью:
   - «На месте» (телефон) — пошаговый: Помещение → Проёмы → Метки → Фото → Замеры → «Осмотр завершён»;
   - «Чистовик» (компьютер) — полный редактор.

   Режимы различаются только интерфейсом; данные и рисование общие.

Ключевые правила модели:
- Помещение хранится как **многоугольник** — список стен-отрезков. В v1 создаётся только прямоугольник, но код развёртки работает от списка отрезков.
- Длины внутри хранятся в **миллиметрах целыми числами**. Ввод — в метрах с запятой (`1,25`), `125 см` переводится автоматически. На листе — до 1 см.
- **Каждый размер** — объект: значение + статус `conditional` («условно») / `measured` («замерено») + способ (рулетка, дальномер, AR) для замеренного.
- Каждый объект хранит **происхождение**: создан вручную или по фото (ссылка на снимок и рамку на нём).
- Все изменения — через действия хранилища; это даёт отмену/повтор и историю состояний.
- Нумерация меток задаётся пользователем (как в протоколе и фототаблице), приложение номера само не перенумеровывает.

## Как работать

- Работаем **строго по этапам `TODO.md`**, по одному. После каждого этапа — работающее приложение.
- Не переходи к следующему этапу, пока пользователь не проверил текущий руками.
- Отмечай выполненное в `TODO.md` (`[x]`). Если по ходу всплыло новое — добавь пунктом в нужный этап или в «После v1», не делай молча.
- Коммит после каждого законченного пункта, сообщение по-русски: что изменилось для пользователя.
- Тесты пишешь сам, на всё расчётное: геометрия, единицы, автопроверки, запись и чтение `.omp`, миграции. Эталон — `examples/`.
- Не удаляй и не переписывай рабочий код «заодно». Только то, что нужно для текущего пункта.

## Язык

- Интерфейс, документы, сообщения коммитов — по-русски.
- Имена в коде (переменные, функции, файлы) — по-английски.
- Комментарии в коде — по-русски, коротко: зачем, а не что.
- Числа на листе — с запятой (`1,25 м`).
